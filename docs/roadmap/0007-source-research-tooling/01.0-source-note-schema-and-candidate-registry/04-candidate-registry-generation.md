# Subtask 01.0/04 - Candidate Registry Generation

**Task:** [01.0 - Source Note Schema & Candidate Registry](/docs/roadmap/0007-source-research-tooling/01.0-source-note-schema-and-candidate-registry/README.md) ·
**Role:** Python Expert · **Depends on:** 02, 03 · **Status:** ⬜ Not started

## Goal

Generate `docs/research/source-candidates.md` deterministically from the source notes, and
add `--check-registry` mode, which fails when the committed registry is stale.

## Baseline

- `load_notes()` exists (from subtask 02).
- `docs/research/` holds `language-ranking-sources.md`, which is authored separately and
  never regenerated.

## Files

| Action | Path                                         | Purpose |
|--------|----------------------------------------------|---------|
| Modify | `scripts/check_source_notes.py`              | Add `render_registry()`, `--write-registry`, `--check-registry` |
| Create | `docs/research/source-candidates.md`         | Generated file with a "do not edit" banner |
| Modify | `tests/scripts/test_check_source_notes.py`   | Registry tests |

## Symbols / fields

| Symbol                | Kind     | Type / signature                                      | Default | Notes |
|-----------------------|----------|-------------------------------------------------------|---------|-------|
| `REGISTRY_PATH`       | constant | `Path`                                                | `REPO_ROOT / "docs/research/source-candidates.md"` | |
| `STATUS_ORDER`        | constant | `tuple[str, ...]`                                     | `("existing", "planned", "candidate", "rejected", "defunct")` | |
| `total_score()`       | function | `(note: SourceNote) -> int`                           | - | Sum of the 6 rubric scores (6-30) |
| `render_registry()`   | function | `(notes: Sequence[SourceNote]) -> str`                | - | Pure; no dates or timestamps in output |
| `--write-registry`    | CLI flag | -                                                     | off | Writes `REGISTRY_PATH` |
| `--check-registry`    | CLI flag | -                                                     | off | Exit 1 with a diff hint if the file ≠ `render_registry()` |

## Behaviour & validators

1. The output starts with
   `<!-- GENERATED by scripts/check_source_notes.py --write-registry; do not edit. -->` and
   a link back to `docs/source-notes/README.md`.
2. There is one `##` section per status, in `STATUS_ORDER`. Sections with no notes are
   omitted.
3. Within a section, rows are sorted by `priority` (p0 → none), then `total_score`
   descending, then `source_id`.
4. The columns are:
   - Source, linking to the note by absolute `/docs/source-notes/<id>.md`;
   - Measures;
   - Access;
   - License;
   - Redistribution;
   - Automation;
   - History from;
   - Cadence;
   - Priority;
   - Score;
   - Roadmap.
5. The `Measures` column is always shown. The registry never presents a single cross-source
   "popularity" number: `Score` is the research rubric score, and its column header links to
   the rubric.
6. Output is byte-identical across runs and platforms: `\n` line endings, a trailing
   newline, and no locale-dependent sorting.

## Success criteria

- [ ] `python scripts/check_source_notes.py --write-registry` produces `docs/research/source-candidates.md`.
- [ ] `python scripts/check_source_notes.py --check-registry` exits 0 immediately afterwards.
- [ ] `python3 scripts/check_doc_links.py docs/research` exits 0.

## Constraints

- `render_registry` is a pure function, so tests call it without touching the filesystem.
